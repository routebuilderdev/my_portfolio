## The Setup

I started from zero — I don't write code and I can't read it. Today I ship full-stack production apps. No CS degree, no bootcamp, no years of tutorials. Just a clear process, an AI agent doing the implementation, and a verification loop I actually run on every change.

Here's exactly how I do it.

## The Workflow

### 1. Problem First

I start with a clear problem statement. Not "build an app" but "a coach driver can't know whether a narrow historic street fits their 14-metre vehicle before they commit to it." The AI can solve constrained problems. Vague requests produce vague code.

### 2. Architecture Discussions

Before any code is generated, I ask the agent to lay out the architecture options and their trade-offs. It writes the analysis; I make the product decision and write down why.

### 3. Iterative Building

Each feature is one prompt cycle:
- Explain what I want, including the behaviour and the failure cases
- AI writes the code and summarises what changed
- I check the claim against the tests, the CI run, and the running app
- Commit and push
- CI/CD runs the suite
- If it is red, the error goes back to the agent

### 4. Testing Is Non-Negotiable

I can't read the implementation, so tests are not a nice-to-have — they are the only evidence I can check. Every feature lands with tests for the behaviour I specified, and CI refuses a red suite. 328 passing tests across the flagship app — 237 backend, 91 frontend, plus 90 Playwright end-to-end checks — is what makes production deployment defensible.

## Key Lessons

- **Constrained problems** produce better code than open-ended ones
- **Monorepo** keeps AI context coherent
- **CI/CD** creates a tight feedback loop
- **The spec and the tests are the contract** — keep both readable, because they are what you verify against
- **AI gives you senior-level implementation on demand** — the product decisions, the constraints, and the quality bar stay yours
